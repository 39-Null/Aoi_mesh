# 使用手册

> 面向日常使用：App 各页面按钮含义、典型操作流程、CLI 参考与常见问题。
> 首次部署请先阅读 [DEPLOY.md](DEPLOY.md)。

## 1. 界面总览

App 有三个页签：**本机 / 组网 / 主控**。

### 1.1 本机

| 区域 | 说明 |
| --- | --- |
| 状态卡 | 远程连接（Telegram Bot）、opencode 服务、代理、开机自启的运行状态 |
| 一键诊断 | 生成诊断报告（结果卡可随时「收起」） |
| 查看日志 | 本机 opencode 日志尾部；支持刷新 / 打开目录 / 收起 |
| 重启连接 | 停止并重新启动远程连接（Bot 与控制端通道） |
| Token 轮换 | BotFather `/revoke` 后粘贴新 token，「更新并重启」即刻换用 |

### 1.2 组网

| 区域 | 说明 |
| --- | --- |
| Hub 连接 | Hub 地址/端口，**保存并同步**会同时写入本机节点配置与控制端配置 |
| 节点配置 | 节点名、加入密钥、opencode 端口与密码（**新密码 + 确认密码**，两次输入一致才会保存）、agent 端口、frpc 路径 |
| └ 按钮 | **保存配置** / **启动节点** / **停止节点** / **刷新状态** / **重置身份** |
| 控制端（可选） | 共享密码（编排派发用，留空取本机节点密码）；高级 → 所有者密钥（一般留空）；**导出到剪贴板 / 从剪贴板导入**用于多控制端一键迁移 |
| 节点状态 | 显示 agent 运行状态与注册结果；节点名与注册身份不一致时提示「启动节点后自动迁移」 |
| agent 日志 | 查看/刷新/收起 agent 运行日志，排障首选 |

### 1.3 主控

| 区域 | 说明 |
| --- | --- |
| 节点管理 | **同步节点（自动配置）**：从注册中心拉取最新节点列表，自动清理已失效节点、自动更新隧道并在隧道运行中时自动重启；**刷新列表**：重新计算在线/可达状态；**清理失效节点**：手动移除注册表中已不存在的节点 |
| 节点隧道（visitor） | **全自动运行**：同步节点或启动 App 时按需自动生成/更新/启动；仅保留「停用/启用」开关（停用会持久保持，直到手动启用）与日志 |
| 编排（opencode-fleet） | 生成 fleet 配置片段（可折叠），粘贴到本机 opencode 的 `mcp` 字段后即可在 opencode 内直接编排多节点 |

## 2. 典型操作

### 修改某节点 opencode 密码

1. 节点设备 →「组网」页 →「opencode」行输入新密码，「确认密码」行再次输入
2. 「保存配置」：两次不一致会直接提示；保存成功会询问是否立即重启本机 opencode（约 1 秒生效）
3. 远程节点：到控制端「主控」页重启对应节点即可

### 修改节点名

节点名是**可变标签**（全网唯一即可），身份由注册 token 保证（不可变）：

1. 「组网」页修改「节点名」并保存（状态栏提示将由旧名迁移为新名）
2. 点「启动节点」（即重启 agent）：自动向 Hub 迁移名称——保留原 token、隧道密钥与端口分配，**无需新加入密钥**
3. 控制端执行一次「同步节点（自动配置）」：新名称出现、旧名称自动清理、隧道自动更新
4. 仅当名称被其他节点占用、或 Hub 为旧版本时，才走「重置身份 + 新加入密钥」流程

### 迁移控制端配置

控制端 A：「组网」页 →「导出到剪贴板」；控制端 B →「从剪贴板导入」——即完成 Hub 连接与节点凭据迁移。

### 手机远程下发

手机向 Bot 发消息 → Bot 所在控制端的 opencode 处理 → 经 MCP/fleet 或 CLI 下发到目标节点 → 回执摘要返回。确保控制端 opencode（如 `4096`）与 Bot 进程在运行。

## 3. CLI 参考（node-ctl）

无需图形环境，`node node-ctl/cli.js <命令>`：

```
list                        列出节点（本地配置 + 注册表在线状态）
status <node>               查询节点 opencode 状态
start|stop|restart <node>   远程启停/重启节点 opencode
fleet-config                输出主控 opencode 的 fleet MCP 配置片段
visitors-config [--out p]   生成主控侧 frpc visitors 配置（stcp 接入）
dispatch <node> "<任务>"    按消息协议派发任务（信封+回执解析，复用会话）
                            选项：--new 强制新会话；--mode one-shot|session；
                                  --timeout 秒（默认300）；--raw 附原始回复
```

示例：

```bash
node node-ctl/cli.js dispatch deepin-1 "查看根分区占用并汇报"
node node-ctl/cli.js dispatch deepin-1 --new "换一个全新会话，执行 uname -a"
```

## 4. 消息协议要点

设备间任务统一使用 **aoi-mesh 消息协议 v1**（完整规范见 [PROTOCOL.md](PROTOCOL.md)）：

- 发送方将任务包装为**信封**（`[aoi-mesh v1]`，含 from / task / mode / reply）
- 接收方执行后返回**回执块**（`[aoi-mesh-result v1]`，含 task / status / summary / artifacts）
- 信息不足时可回**澄清块**（question），发送方补充后继续
- 解析器带宽松回退：小模型未严格按格式回复时仍可提取有效信息

## 5. 常见问题

| 问题 | 处理 |
| --- | --- |
| 保存配置时提示「两次输入的密码不一致」 | 重新在「确认密码」中输入相同密码；不改密码时两处都留空即可 |
| 提示「节点名已变更」 | 保存后点「启动节点」即自动迁移，无需新密钥；名称冲突或旧版 Hub 才需「重置身份」 |
| 节点`在线`但访问不通 | 「组网」页看 agent 日志；「主控」页确认隧道未被手动停用 |
| 同步后看不到某节点 | 该节点可能离线或被吊销；先确认节点在线，再「刷新列表」 |
| 隧道端口冲突 | 「主控」页停止隧道后重新启动，按当前节点列表重新分配回环端口 |
| 想给其他设备开新名额 | 用任一已入网设备向 Hub 生成加入密钥（部署文档 §2），无需固定管理员 |
